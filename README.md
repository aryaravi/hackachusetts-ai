# OmniGridX

OmniGridX is a sample-only Massachusetts commercial-site energy screening demo. A React interface compares existing operation, a documented solar-first rule, and SciPy MILP–optimized dispatch generated by a Python backend. This optimization is constrained grid intelligence, not AI forecasting. Every published schedule passes a separate constraint checker.

> This Fast Judge MVP uses synthetic bundled data only. Cost is a `Screening_Estimate`; outage results are deterministic `Outage_Service_Screening`. It has no AI, weather, or demand forecasting. It also has no verified tariff, customer data, upload path, local-grid feasibility assessment, or autonomous control.

## Judge setup and demo

Requirements: Git, Python **3.13.13**, Node **18.20.8**, and npm. From a fresh machine:

```bash
git clone https://github.com/aryaravi/hackachusetts-ai.git
cd hackachusetts-ai
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
make demo
```

Open <http://127.0.0.1:8000>. `make demo` installs the exact frontend lockfile, builds React, and starts the Python service on loopback. It requires no login or data upload and reads only the bundled synthetic scenario. Stop it with `Ctrl-C`.

The API surface is intentionally limited:

- `GET /healthz` — ready only after the bundled sample is initialized
- `GET /api/sample-report` — deterministic report JSON
- `POST /api/sample-run` — rerun bundled bytes; request bodies are rejected
- `GET /` — React comparison interface

## Verification and packaging

With the virtual environment active, run the complete local check from the repository root:

```bash
make check
```

`make check` builds the frontend, runs the Python tests and strict type check, builds both Python package formats, and validates the draft submission structure. It uses no customer data or remote data adapters. After the human-owned Render URL, team, representative, video, and final commit fields are populated, run `python -m omnigridx.submission` for strict final validation.

## Architecture

- `frontend/` — React 19 interface built with Vite
- `src/omnigridx/domain/` — immutable units, records, simulation, and independent constraints
- `src/omnigridx/application/` — dispatch, optimization, metrics, orchestration, and reporting
- `src/omnigridx/infrastructure/` — bundled sample/reference metadata, SciPy, SQLite, and local snapshots
- `src/omnigridx/web/` — Starlette API, React static host, and hosted smoke validator

The app is one modular monolith. React does not calculate metrics; it renders the immutable report returned by Python.

## Render judge deployment

`render.yaml` defines one free Python web service. A team member must link the public repository in Render and deploy the blueprint. The build installs the locked React dependencies, emits static assets, and installs Python; startup binds Uvicorn to platform `$PORT` with `OMNIGRIDX_MODE=demo-public`.

Free hosting may cold-start for several minutes. State is rebuilt from bundled synthetic bytes on every boot and is ephemeral; no persistence is claimed. Free-tier limits and availability can change. If hosted access is unavailable, use `make demo` locally.

After deployment, record the URL and public-mode report fingerprint in `submission-metadata.json`, then run:

```bash
make smoke PUBLIC_DEMO_URL=https://YOUR-SERVICE.onrender.com REPORT_FINGERPRINT=YOUR_SHA256
```
